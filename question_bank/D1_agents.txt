@ D1 1.1 | Customer support
Your support agent's loop sometimes ends before it has called process_refund, even though the customer clearly asked for a refund. The loop currently stops whenever the response contains any text. What should the loop check instead?
+ Whether stop_reason is "tool_use" (continue) or "end_turn" (stop) :: stop_reason is the reliable signal. Claude can write text and request a tool in the same response.
- Whether the text contains words like "done" or "complete" :: Parsing natural language is unreliable and is an anti-pattern the exam names explicitly.
- Whether 3 iterations have passed :: A fixed cap as the main stop cuts off longer tasks. Caps are only a safety net.
- Whether the last message is longer than 50 characters :: Message length says nothing about whether Claude still needs a tool.

@ D1 1.6 | Multi-agent research
When should you NOT add subagents to a workflow?
+ For small, sequential tasks that share state, where doing it directly is simpler :: Subagents add cost and coordination overhead.
- When the task has several independent research directions :: That's exactly where parallel subagents help.
- When verbose exploration would flood the main context :: Subagents are good at isolating that.
- When you need different tool sets for different parts :: Scoped subagents fit that well.
