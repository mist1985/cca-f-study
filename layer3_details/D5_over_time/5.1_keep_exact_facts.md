# 5.1 · Keeping exact facts in long conversations

📍 **Map:** Whole picture → 5. Over time → **5.1 Keep exact facts**  ·  ⏱ 3 min

## The one rule
> Summaries blur numbers. Keep a **"case facts" block** that's **never summarized** and is sent every time.

## Picture it
Message 3: "budget €48,500, deadline 3 March." Message 60, after summarizing: "customer discussed budget". Gone.

## Know these 🎯
- **Progressive summarization** loses numbers, percentages, dates and what the customer expects.
- **Lost in the middle:** Claude reads the **start and end** of long input best and misses the **middle**.
  → Put **key findings first**, use clear section headers.
- Tool results pile up: 40+ fields per order lookup when 5 matter → **trim to the relevant fields**.
- Send the **full conversation history** with every request (Claude has no memory).
- Multi-issue chats → keep **structured issue data** (order IDs, amounts, statuses) in a separate layer.
- Helpers should return **structured facts + metadata** (dates, sources), not long reasoning, when the next agent has little room.

## ⚠️ Exam traps
| ❌ Wrong | ✅ Right |
|---|---|
| Trust the summary for exact numbers | Case facts block |
| Bigger context window | Middle still gets lost |
| Keep all 40 fields | Trim to what matters |
| Trim the helper's output after it arrives | Make the helper send structured facts |

<details><summary>🧠 Say it out loud: where do the exact amounts and order numbers live?</summary>

In a persistent case facts block, outside the summarized history, included in every prompt.
</details>
