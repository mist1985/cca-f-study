# 5.4 · Context in big codebases

📍 **Map:** Whole picture → 5. Over time → **5.4 Big codebases**  ·  ⏱ 3 min

## The one rule
> Keep the main context **clean**: send noisy work to helpers, and **write findings to files**.

## Picture it
A long session fills up. Claude starts talking about "typical patterns" instead of the specific classes it found an hour ago.

## Know these 🎯
- Symptom of context degradation: **vague, generic, inconsistent answers**.
- **Helpers for specific questions** ("find all test files", "trace the refund flow") → main agent keeps the big picture.
- **Scratchpad files**: write key findings to disk and refer back to them later.
- Between phases: **summarize** phase 1, then **inject that summary** when starting phase 2.
- **Crash recovery:** each agent saves its state to a **manifest file**. The lead **loads it on resume**.
- **`/compact`** when verbose exploration fills the context.

## ⚠️ Exam traps
| ❌ Wrong | ✅ Right |
|---|---|
| Main agent reads everything itself | Helpers for specific questions |
| Rely on memory of what was found | Scratchpad file |
| Restart from zero after a crash | Manifest, reload on resume |

<details><summary>🔬 Bonus (beyond the official guide)</summary>

`/clear` = wipe (only between unrelated tasks). `/compact` = summarize and continue. Path-scoped rules reload only when a matching file is touched again.
</details>

<details><summary>🧠 Say it out loud: how does a crashed multi-agent job continue?</summary>

Each agent wrote its state to a manifest. The lead loads it and injects it into the prompts.
</details>
