# 3.1 · CLAUDE.md: the note on Claude's desk

📍 **Map:** Whole picture → 3. Claude Code → **3.1 CLAUDE.md**  ·  ⏱ 3 min

## The one rule
> Team rules go in the **project** CLAUDE.md (in git). Your personal file is **never shared**.

## Picture it
Every morning Claude forgets yesterday. CLAUDE.md is the note pinned to its desk. Some notes are on *your* desk only, some are in the shared office.

## Know these 🎯
| Level | Path | Shared? |
|---|---|---|
| User | `~/.claude/CLAUDE.md` | ❌ only you |
| Project | `CLAUDE.md` or `.claude/CLAUDE.md` | ✅ via git |
| Directory | `subfolder/CLAUDE.md` | ✅ for that folder |

- New teammate isn't getting the rules? → They're in someone's **user** file. Move them to the **project** file.
- `@import` pulls other files in (e.g. each package imports only the standards it needs).
- Huge CLAUDE.md → split into `.claude/rules/` (`testing.md`, `api-conventions.md`, `deployment.md`).
- **`/memory`** → check which memory files are loaded.
- CLAUDE.md is a **note**, not a lock.

## 👀 What it looks like
```
~/.claude/CLAUDE.md                 ← only you: "I like short answers"
my-repo/CLAUDE.md                   ← team: "Python 3.12. Run tests with make test."
my-repo/packages/billing/CLAUDE.md  ← that folder: "Money is always integer cents."
```
Modular CLAUDE.md with imports:
```markdown
# packages/billing/CLAUDE.md
@../../docs/standards/money.md
@../../docs/standards/api-errors.md
```
Splitting a big file:
```
.claude/rules/testing.md
.claude/rules/api-conventions.md
.claude/rules/deployment.md
```
**Piece by piece**
- The project file is **in git**, so every teammate gets it.
- `@path` imports pull in only the standards that package needs.
- `/memory` → see which of these files are actually loaded.

## ⚠️ Exam traps
| ❌ Wrong | ✅ Right |
|---|---|
| Team rules in `~/.claude/CLAUDE.md` | Project CLAUDE.md |
| Block secrets with a CLAUDE.md line | Permission deny rule or hook |

<details><summary>🧠 Say it out loud: a new developer's Claude ignores the team style. Why?</summary>

The style rules sit in someone's user-level file, which isn't shared through git.
</details>
