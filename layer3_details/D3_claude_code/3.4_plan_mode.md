# 3.4 · Plan mode vs just doing it

📍 **Map:** Whole picture → 3. Claude Code → **3.4 Plan mode**  ·  ⏱ 3 min

## The one rule
> **Big, multi-file, or several valid approaches → plan mode.** Small and clear → direct execution.

## Picture it
Fixing a typo? Just do it. Splitting a monolith into microservices? Look at the blueprint first.

## Know these 🎯
| Plan mode ✅ | Direct execution ✅ |
|---|---|
| Monolith → microservices | Single-file bug with a clear stack trace |
| Library migration touching 45+ files | Add one date validation check |
| Choosing between integration approaches | Add one validation to one function |

- Plan mode = **explore and design safely before changing anything** → avoids expensive rework.
- **Explore subagent** = does the noisy searching and returns a **summary** → your main context stays clean.
- Combine: **plan** the migration, then **execute directly** to implement it.

## ⚠️ Exam traps (this is sample question #5)
| ❌ Wrong | ✅ Right |
|---|---|
| Start coding, let boundaries "emerge" | Plan first. Late discoveries = rework |
| Direct execution with detailed instructions | Assumes you already know the answer |
| Switch to plan mode only if it gets hard | The complexity is already known |
