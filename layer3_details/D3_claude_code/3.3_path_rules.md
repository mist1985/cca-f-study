# 3.3 · Path-specific rules

📍 **Map:** Whole picture → 3. Claude Code → **3.3 Path rules**  ·  ⏱ 3 min

## The one rule
> Conventions for files **spread across many folders** → **one rule file with a glob pattern**.

## Picture it
A sticky note that pops up only when you open the test drawer, wherever in the building that drawer is.

## Know these 🎯
```yaml
# .claude/rules/testing.md
---
paths: ["**/*.test.tsx"]
---
All tests use describe/it and ...
```
- Loads **only when editing matching files** → less noise, fewer tokens.
- `**/*.test.tsx` matches test files **anywhere**. Other example: `paths: ["terraform/**/*"]`.
- **Glob rule beats a CLAUDE.md in every folder** when files are scattered.

## ⚠️ Exam traps (this is sample question #6)
| ❌ Wrong | ✅ Right |
|---|---|
| Everything in root CLAUDE.md with headers | Relies on Claude guessing |
| A skill per code type | Needs invoking. Not automatic |
| CLAUDE.md in each subfolder | Can't follow scattered test files |
| ✅ | `.claude/rules/` + glob `paths` |

<details><summary>🧠 Say it out loud: test files live next to their code in 50 folders. Where do test conventions go?</summary>

One `.claude/rules/` file with `paths: ["**/*.test.tsx"]`.
</details>
