# 1.1 · The loop

📍 **Map:** Whole picture → 1. Agents → **1.1 The loop**  ·  ⏱ 3 min

## The one rule
> Keep looping **while** `stop_reason == "tool_use"`. Stop when it's `"end_turn"`.

## Picture it
Claude is a consultant you can only reach by letter. It writes: *"Please look up order 123."* You look it up and write back. Repeat until Claude says it's finished.

## Know these 🎯
- Each round: send request → read `stop_reason` → run the tool → **add the result to the conversation** → send again.
- Claude decides which tool comes next (**model-driven**). Not a fixed decision tree in your code.
- `tool_result` goes back in a **user** message, with the same id as the `tool_use`.

## 👀 What it looks like
```python
messages = [{"role": "user", "content": task}]
while True:
    resp = client.messages.create(model=MODEL, max_tokens=4096,
                                  tools=TOOLS, messages=messages)
    messages.append({"role": "assistant", "content": resp.content})
    if resp.stop_reason != "tool_use":      # "end_turn" → finished
        break
    results = [{"type": "tool_result", "tool_use_id": b.id,
                "content": run_tool(b.name, b.input)}
               for b in resp.content if b.type == "tool_use"]
    messages.append({"role": "user", "content": results})
```
**Piece by piece**
- `messages` keeps the **whole history**. It's re-sent every round, because Claude has no memory.
- `stop_reason != "tool_use"` → leave the loop. That's the **only** finish signal.
- Each tool answer is a `tool_result` with the **same id**, sent back as a `user` message.
- No `if "done" in text`, and no `for i in range(5)` as the main stop.

## ⚠️ The 3 wrong ways to stop (the exam names these)
| ❌ Wrong | ✅ Right |
|---|---|
| Read Claude's words ("I'm done!") | Check `stop_reason` |
| A fixed step cap as the main stop | A cap is only a safety net |
| "Claude wrote text, so it's finished" | Text can come *with* a tool call. Check `stop_reason` |
