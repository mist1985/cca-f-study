# 2.5 · Built-in tools

📍 **Map:** Whole picture → 2. Tools → **2.5 Built-in tools**  ·  ⏱ 3 min

## The one rule
> **Grep = search INSIDE files. Glob = find files by NAME.** Search first, then read only what matters.

## The toolbox 🎯
| Tool | Job | Example |
|---|---|---|
| **Grep** | search file **contents** | who calls `parseInvoice`? where's this error message? |
| **Glob** | match file **paths** | `**/*.test.tsx` |
| **Read** | load a whole file | |
| **Write** | write a whole file | |
| **Edit** | change one **unique** piece of text | |
| **Bash** | run commands | |

## Know these 🎯
- **Edit fails because the text isn't unique → Read + Write** (fallback in the official guide).
- Explore step by step: **Grep finds the entry point → Read follows the imports.** Don't read every file up front.
- Wrapper modules: first list all **exported names**, then Grep for each name.

## 👀 What it looks like
```
Glob  "**/*.test.tsx"              → every test file (by NAME)
Grep  "processRefund\("            → every file that CALLS it (by CONTENT)
Read  src/billing/refund.ts        → read the entry point, follow its imports
Edit  old: "retries = 3"  new: "retries = 5"   → only if that text is unique
      ↳ not unique? → Read the whole file, Write the corrected version
```
Tracing through a wrapper module:
```
1. Read  src/api/index.ts  → it re-exports: createOrder, refundOrder, getStatus
2. Grep  each of those names across the codebase
```
**Piece by piece**
- Start **narrow** (Grep/Glob), read **only** what matters, then follow the trail.
- Edit needs a **unique anchor**. Read + Write is the reliable fallback.

## ⚠️ Exam traps
| ❌ Wrong | ✅ Right |
|---|---|
| Glob to find who calls a function | Grep |
| Grep to find all test files | Glob |
| Read the whole repo first | Search first, read selectively |
