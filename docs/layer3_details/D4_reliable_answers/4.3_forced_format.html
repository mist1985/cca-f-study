4.3 Forced format (tool use + JSON schema)

📍 Map: Whole picture → 4. Answers → 4.3 Forced format · ⏱ 3 min

The one rule

A schema guarantees the SHAPE. It never guarantees the TRUTH.

Picture it

A form Claude must fill in, instead of a letter it writes. The form always has the right boxes, but someone can still write the wrong number in a box.

Know these 🎯

  • Most reliable way to get valid structured output: define a tool whose input schema is your data shape, then read the tool_use input. → No JSON syntax errors.
  • Still possible: semantic errors (line items don't add up to the total, value in the wrong field).
  • tool_choice:
    • "any" → must call a tool. Use when several extraction schemas exist and the document type is unknown.
    • forced {"type":"tool","name":"extract_metadata"} → that tool runs first, before enrichment.
  • Schema design against made-up values:
    • Info may be missing → field optional / nullable.
    • Enums: add "unclear" and "other" + a detail text field.
  • Add format normalization rules in the prompt next to the schema (dates, units).

👀 What it looks like

extract_invoice = {
  "name": "extract_invoice",
  "description": "Record the fields of one supplier invoice.",
  "input_schema": {
    "type": "object",
    "properties": {
      "vendor":       {"type": "string"},
      "stated_total": {"type": "number"},
      "po_number":    {"type": ["string", "null"]},           # may be missing
      "category":     {"enum": ["coffee", "packaging", "shipping", "other", "unclear"]},
      "category_detail": {"type": ["string", "null"]}         # filled when "other"
    },
    "required": ["vendor", "stated_total", "po_number", "category"]
  }
}
resp = client.messages.create(..., tools=[extract_invoice],
        tool_choice={"type": "tool", "name": "extract_invoice"})
data = next(b.input for b in resp.content if b.type == "tool_use")

Piece by piece

  • The answer arrives as the tool's input, so it always matches the schema.
  • ["string", "null"] = Claude may honestly say "not there".
  • "other" + detail and "unclear" stop Claude forcing a wrong category.
  • Still possible: valid shape, wrong numbers → validate (4.4).

🧠 Say it out loud: why make a field nullable?

If the document doesn't have it, Claude can say null instead of making something up.
