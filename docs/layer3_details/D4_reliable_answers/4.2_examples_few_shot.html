4.2 Few-shot examples

📍 Map: Whole picture → 4. Answers → 4.2 Few-shot · ⏱ 3 min

The one rule

Instructions alone give inconsistent output? → Show 2–4 targeted examples.

Picture it

Explaining a form in words is hard. Handing someone 3 filled-in forms, one tricky and one with a missing value, works instantly.

Know these 🎯

  • Few-shot = the most effective way to get consistent format when instructions alone fail.
  • Best for ambiguous cases: show why one choice beat the other plausible ones.
  • Helps Claude generalize to new patterns, not just copy.
  • Show the exact output format (location, issue, severity, suggested fix).
  • Show acceptable code vs a real issue → fewer false positives.
  • Extraction: show different document layouts (inline citations vs bibliography). Show missing info → null → less made-up data.

👀 What it looks like

<examples>
  <example>
    <input>Lead time: ships in ~2 wks</input>
    <output>{"lead_time_days": 14}</output>
  </example>
  <example>
    <input>Delivery: 3-5 business days</input>
    <output>{"lead_time_days": 5}</output>
    <why>Range given: use the upper bound, so the promise is safe.</why>
  </example>
  <example>
    <input>Contact sales for availability.</input>
    <output>{"lead_time_days": null}</output>
    <why>Not stated. null, never a guess.</why>
  </example>
</examples>

Piece by piece

  • 3 different formats → Claude learns the rule, not one pattern.
  • <why> shows the reasoning for an ambiguous case.
  • The null example teaches "don't invent".
