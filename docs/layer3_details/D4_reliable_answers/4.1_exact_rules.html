4.1 Exact rules beat "be careful"

📍 Map: Whole picture → 4. Answers → 4.1 Exact rules · ⏱ 3 min

The one rule

Say exactly what to report and what to skip. Words like "be conservative" do nothing.

Picture it

The reviewer flags 30 "problems", 25 of them nonsense. Developers stop reading, including the 5 real ones.

Know these 🎯

  • ❌ "Check that comments are accurate" → ✅ "Flag a comment only when what it claims contradicts what the code does."
  • ❌ "Only report high-confidence findings" → doesn't improve precision.
  • ✅ Report: bugs, security. Skip: minor style, local patterns.
  • One noisy category ruins trust in all of them → temporarily switch that category off while you fix its prompt.
  • Define each severity level with a concrete code example.

👀 What it looks like

❌ Vague:

Review the code carefully. Be conservative and only report high-confidence issues.

✅ Explicit:

Report ONLY:
- bugs: code that crashes or returns wrong results
- security: injection, leaked secrets, missing auth checks
- comments whose claim CONTRADICTS what the code does
Do NOT report: style, naming, formatting, patterns used consistently in this repo.

Severity:
- critical: e.g. db.query("SELECT * FROM users WHERE id=" + req.params.id)
- minor:    e.g. missing null check on an optional config value with a default

Piece by piece

  • Include and exclude lists give a clear yes/no test for each finding.
  • Each severity has a code example, so labels stay consistent.

⚠️ Exam traps

❌ Wrong✅ Right
"Be conservative"Categorical include/skip list

🧠 Say it out loud: why doesn't "only high-confidence findings" work?

It gives Claude no clear line to decide by. Exact categories do.
