4.4 Check + retry

📍 Map: Whole picture → 4. Answers → 4.4 Check + retry · ⏱ 3 min

The one rule

Retry with the exact error. But if the info isn't in the document, retrying is useless.

Picture it

The form is perfect, but the items add up to €940 and the total says €1,040. Your code catches it and asks again, saying exactly what's wrong.

Know these 🎯

  • Two kinds of errors:
    • Syntax/schema (broken JSON) → removed by tool use (4.3).
    • Semantic (doesn't add up, wrong field) → your validation code (e.g. Pydantic) + retry.
  • A good retry sends: original document + failed extraction + the specific errors.
  • Retry works for: format mismatches, structural mistakes.
  • Retry fails when: the info is absent, or only in another document not provided.
  • Self-check fields: extract calculated_total and stated_total + a conflict_detected flag.
  • Feedback loop: add a detected_pattern field to findings → see which patterns developers dismiss → fix those.

⚠️ Exam traps

❌ Wrong✅ Right
Retry the same prompt unchangedAdd the specific errors
Retry until the tax ID appearsIt's absent: null + flag
🧠 Say it out loud: when will a retry NOT help?

When the information isn't in the document Claude was given.
