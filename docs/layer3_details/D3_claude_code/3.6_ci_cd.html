3.6 Claude Code in CI/CD

📍 Map: Whole picture → 3. Claude Code → 3.6 CI/CD · ⏱ 3 min

The one rule

On a server nobody watches: -p (non-interactive) + --output-format json --json-schema (machine-readable).

Picture it

Claude reviews every pull request at 3 a.m. Nobody is there to answer questions. The result must be readable by another program.

Know these 🎯

  • claude -p "..." (or --print) → run once, print, exit. Without it the job hangs waiting for input.
  • --output-format json + --json-schema → structured findings → post as inline PR comments.
  • CLAUDE.md gives context to CI runs: testing standards, fixtures, review criteria.
  • Independent review: the session that wrote the code is worse at reviewing it.
  • Re-review after new commits → include the previous findings and report only new or still-open issues (no duplicate comments).
  • Generating tests → give it the existing tests so it doesn't suggest duplicates.

👀 What it looks like

claude -p "Review this PR diff for bugs and security issues. \
Previous findings are in prior_findings.json: report ONLY new or still-unresolved issues." \
  --output-format json \
  --json-schema '{"type":"object","properties":{"findings":{"type":"array","items":{
      "type":"object","properties":{"file":{"type":"string"},"line":{"type":"integer"},
      "severity":{"enum":["critical","minor"]},"issue":{"type":"string"}},
      "required":["file","line","severity","issue"]}}},"required":["findings"]}'

Piece by piece

  • -p = run once, no waiting for a human.
  • --output-format json + --json-schema = findings a script can post as inline PR comments.
  • Prior findings in context = no duplicate comments on re-runs.
  • CLAUDE.md in the repo gives the CI run the team's testing standards and fixtures.
