5.3 Reporting failures honestly (multi-agent)

📍 Map: Whole picture → 5. Over time → 5.3 Honest failures · ⏱ 3 min

The one rule

Never fake success. Never stop everything for one failure. Send structured error context.

Picture it

A helper's web search crashes and it quietly says "nothing found". The final report says "no competitors in Germany". Wrong, and nobody knows.

Know these 🎯

  • Structured error = failure type + what was tried + partial results + other options.
  • Access failure (timeout) ≠ valid empty result (searched, nothing there).
  • A generic "search unavailable" hides useful details.
  • 2 opposite mistakes (both wrong):
    • 🙈 Hide the error (return empty "success").
    • 💥 Kill the whole workflow on one failure.
  • Helpers retry temporary errors themselves, and pass up only what they can't fix.
  • Final report gets coverage notes: which findings are solid, where the gaps are.

⚠️ Exam traps (this is sample question #8)

❌ Wrong✅ Right
Retry, then generic "unavailable"Structured context
Empty result marked successThat's hiding it
Kill the whole research runContinue + note the gap
🧠 Say it out loud: what goes into a good error from a helper?

Failure type, what it tried, partial results, possible alternatives.
