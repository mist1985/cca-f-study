1.6 Splitting a job

📍 Map: Whole picture → 1. Agents → 1.6 Splitting a job · ⏱ 3 min

The one rule

Predictable steps → fixed chain (prompt chaining). Open-ended → adaptive plan.

Picture it

  • Job A: review 12 files, then check they fit together. Steps known → a recipe.
  • Job B: "Add tests to this legacy codebase." Steps unknown → a detective.

Know these 🎯

  • Prompt chaining = fixed steps, each working on the last one's output.
  • Adaptive = map the structure → find high-impact areas → prioritized plan → adjust as you discover things.
  • Too many files in one pass → attention dilution: shallow comments, missed bugs, contradictions.
    Fix: one pass per file + a separate cross-file integration pass.

⚠️ Exam traps (this is sample question #12)

❌ Wrong✅ Right
Bigger model / bigger context windowPer-file passes + integration pass
Make developers split their PRsFix the system, not the people
Run 3 reviews, keep only issues found twiceThat hides real bugs
Fixed pipeline for an open investigationAdaptive plan
🧠 Say it out loud: a 14-file review is inconsistent and contradicts itself. Fix?

Review each file on its own, then one extra pass for how the files connect.
