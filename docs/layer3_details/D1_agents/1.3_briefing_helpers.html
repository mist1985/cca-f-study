1.3 Briefing helpers (subagent setup)

📍 Map: Whole picture → 1. Agents → 1.3 Briefing helpers · ⏱ 3 min

The one rule

A helper knows only what's in its brief. Write everything it needs.

Picture it

A handover note to a temp worker: everything on one page. "Check the config" is useless. Which config? Where?

Know these 🎯

  • Helpers are started with the Task tool. The lead's allowedTools must include "Task".
    (In current products it's renamed "Agent". On the exam, it's Task.)
  • Helpers don't inherit the lead's chat or share memory. Pass everything in the prompt.
  • Put complete earlier findings into the brief (e.g. search results → synthesis helper).
  • Use a structured format that keeps content separate from metadata (URL, document name, page number). That keeps sources attached.
  • Parallel = several Task calls in one reply. Not one per turn.
  • Brief = goals + quality criteria, not step-by-step instructions.
  • AgentDefinition = description + system prompt + tool restrictions for each helper type.

👀 What it looks like

options = ClaudeAgentOptions(
    allowed_tools=["Task", "Read", "Grep"],          # "Task" = may start helpers
    agents={
        "synthesis": AgentDefinition(
            description="Combines research findings into a cited report.",
            prompt="Goal: a report answering the question. Every claim must keep its source. "
                   "Mark gaps explicitly.",
            tools=["Read"],                          # only what its job needs
        )
    },
)

A good brief includes the earlier findings, structured:

<finding>
  <claim>EU coffee imports grew 4% in 2025</claim>
  <source>ico.org/report-2025.pdf, page 12</source>
  <date>2025-11-03</date>
</finding>

Piece by piece

  • description = when the coordinator should use this helper.
  • prompt = the helper's system prompt: goals + quality criteria, not steps.
  • tools = least privilege (→ 2.3).
  • Content (claim) is kept separate from metadata (source, date), so attribution survives.

The lead sends 3 Task calls in one single reply.
